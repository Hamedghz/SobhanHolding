# Seed امن نصب تازه

## هدف

`install.php` بعد از ایجاد schema و حساب مدیر، رجیستری seedهای پایه را از مسیر مشترک `Installer::seedFreshDatabase()` اجرا می‌کند. هدف این مرحله جلوگیری از پنل خالی در نصب تازه است، بدون اینکه اعداد عملیاتی یا گزارش ساختگی وارد سامانه شود.

## داده‌های ایجاد یا تعمیرشده

- تنظیمات پایه سایت و ثبت ماژول‌ها
- ساختار مرجع فروش و لاین‌های A تا D
- دوره‌های سیستمی تاریخ
- بانک آزمون سازمانی و تنظیمات پایه منابع انسانی
- مجوزهای پایه
- تنظیمات پیش‌فرض ویجت‌های داشبورد برای همه دامنه‌های تعریف‌شده
- نگاشت‌های پایه سرستون برای تمام قالب‌های مرکز Import؛ نگاشت سفارشی موجود بازنویسی نمی‌شود

seed داشبورد از `DashboardModule::repair()` استفاده می‌کند و `data_source_key`های داشبورد مدیر فروش را به Viewهای گزارش canonical متصل می‌کند. تنظیمات موجود کاربر در اجرای دوباره بازنویسی نمی‌شوند.

Repair ساختار سازمانی وجود جدول و ستون را با همان اتصال `PDO` دریافت‌شده از نصب‌کننده بررسی می‌کند. به این ترتیب اجرای nested seed یا تعمیر چندباره روی دیتابیس تازه به اتصال سراسری دیگری وابسته نیست و ستون‌های موجود دوباره با `ALTER TABLE` افزوده نمی‌شوند.

## داده‌هایی که ساخته نمی‌شوند

نصب‌کننده در جدول‌های عملیاتی فروش، خرید، موجودی و تردد ردیف آزمایشی وارد نمی‌کند. داشبوردهای عددی تا زمان Import معتبر، Commit کنترل‌شده و تعیین Batch فعال باید empty state راهنما نمایش دهند. Excel ورودی است و منبع دائمی گزارش نیست.

## پیش‌نیازها

- PHP 8.1 یا جدیدتر
- `pdo_mysql`
- `json`
- `mbstring`
- `fileinfo` برای تشخیص امن MIME فایل‌های ورودی
- `zip` / `ZipArchive` برای ساخت و خواندن قالب‌های Excel
- دیتابیس MySQL/MariaDB با charset سازگار با `utf8mb4`
- host و port معتبر دیتابیس؛ پورت پیش‌فرض 3306 است و پورت اختصاصی نیز پشتیبانی می‌شود

نصب‌کننده نبودن هر پیش‌نیاز را قبل از شروع اعلام می‌کند. خطای فنی seed در رابط کاربر نمایش داده نمی‌شود و فقط شناسه seed در لاگ امن ثبت می‌شود.
فرم نصب یک CSRF مستقل از دیتابیس دارد. خطای PDO/SQL، مسیر سرور یا جزئیات اتصال در UI نمایش داده نمی‌شود؛ لاگ نیز فقط نوع استثنا و کد پاک‌سازی‌شده را ثبت می‌کند.
اطلاعات اتصال در `config/local.php` با دسترسی محدود ذخیره می‌شود و این فایل در `.gitignore` قرار دارد. `config/config.php` قالب بدون secret است؛ خواندن آن برای سازگاری نصب‌های قدیمی حفظ شده است.

## تکرارپذیری و ایمنی

- رجیستری seedها با حالت safe اجرا می‌شود.
- اجرای دوباره شمارش داده‌های پایه را بی‌دلیل افزایش نمی‌دهد.
- داده سفارشی آزمون حذف نمی‌شود؛ رکورد seed قدیمی در صورت نیاز فقط archive/inactive می‌شود.
- هیچ `DROP`، `TRUNCATE` یا حذف داده عملیاتی در این مسیر وجود ندارد.
- اتصال موقت نصب در `finally` از `Database` خارج و وضعیت قبلی اتصال بازگردانده می‌شود.

## اعتبارسنجی

آزمون‌های مرتبط:

```powershell
php tests/installer_safe_seed_contract_test.php
php tests/installer_local_config_test.php
php -d extension=pdo_mysql -d extension=mbstring tests/fresh_install_seed_registry_integration_test.php
php -d extension=pdo_mysql -d extension=mbstring tests/dashboard_preferences_module_integration_test.php
```

تست integration باید روی دیتابیس ایزوله اجرا شود. معیار قبولی شامل اجرای موفق دوباره seedها، ثابت ماندن شمارش‌ها، حفظ داده سفارشی و خالی ماندن جدول‌های عملیاتی است.

پذیرش مرورگر باید علاوه بر پیام موفقیت نصب، ورود مدیر، نمایش داشبورد، صفر بودن خطای console، دانلود قالب‌های Import و پاسخ 403 نصب مجدد را کنترل کند. config و lock آزمایشی پس از پایان باید حذف شوند.

## Rollback

Rollback کد شامل بازگرداندن فراخوانی خودکار seed از `install.php` است. جدول یا داده پایه در rollback خودکار حذف نمی‌شود. هر حذف فیزیکی احتمالی به طرح جداگانه، نسخه پشتیبان و تأیید انسانی نیاز دارد.
