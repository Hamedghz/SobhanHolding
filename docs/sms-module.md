# ماژول پیامکی سبحان

## دامنه این فاز

این فاز اتصال SOAP سرویس BazyabPayam، تنظیم امن حساب، آزمون اعتبار، ارسال دستی در بسته‌های حداکثر ۹۰ شماره و ثبت نتیجه هر بسته و گیرندگان را فراهم می‌کند. قالب‌ها، صف زمان‌بندی‌شده، همگام‌سازی تحویل و اتصال به ماژول‌های عملیاتی در این فاز فعال نشده‌اند.

## راه‌اندازی

افزونه‌های PHP `soap` و `openssl` باید فعال باشند. کلید رمزنگاری ترجیحاً با متغیر محیطی `SOBHAN_SMS_ENCRYPTION_KEY` تنظیم شود؛ در غیر این صورت برنامه یک کلید محلی نادیده‌گرفته‌شده در `config/sms.key` می‌سازد. سپس کاربر دارای مجوز `sms.manage` از «تنظیمات ← سامانه پیامکی» اطلاعات حساب را ذخیره و اعتبار را آزمایش می‌کند.

## امنیت و رفتار

- رمز با AES-256-GCM ذخیره می‌شود و دوباره در UI نمایش داده نمی‌شود.
- درخواست‌ها نیازمند ورود، مجوز و CSRF معتبر هستند.
- شماره‌های ایران normalize و validate و موارد تکراری حذف می‌شوند.
- خطاهای خام SOAP فقط در لاگ فنی سرور نوشته می‌شوند؛ UI پیام فارسی عمومی دریافت می‌کند.
- ثبت هر بسته و گیرندگان آن در یک تراکنش دیتابیس انجام می‌شود.
- API مبتنی بر URL و قراردادن رمز در query string غیرفعال است.
- schema افزایشی است و از `CREATE TABLE IF NOT EXISTS` در `SmsModule::repair()` و `database/schema.sql` استفاده می‌کند.

## جداول و rollback

جداول افزوده‌شده `sms_settings`، `sms_messages` و `sms_message_recipients` هستند. rollback خودکار مخرب ارائه نشده است؛ برای غیرفعال‌سازی امن، تنظیم سرویس را غیرفعال و دسترسی `sms.manage` را بردارید. حذف جدول یا داده فقط با تأیید انسانی و پشتیبان معتبر مجاز است.

## اعتبارسنجی

تست قراردادی `tests/sms_module_contract_test.php` وجود الزامات schema، امنیت، batch و صفحات را کنترل می‌کند. تست واقعی اعتبار/ارسال به دسترسی شبکه، SOAP فعال و اطلاعات معتبر سرویس‌دهنده نیاز دارد.

محدودیت شناخته‌شده: سرویس‌دهنده API رزرو/تراکنش توزیع‌شده ارائه نکرده است؛ بنابراین اگر ارسال خارجی موفق شود اما دیتابیس بلافاصله پس از آن از دسترس خارج شود، ثبت گزارش آن بسته تضمین‌پذیر نیست و باید با گزارش پنل سرویس‌دهنده تطبیق داده شود.
