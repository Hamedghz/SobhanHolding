# یکپارچگی داشبورد، پلنر و تنظیمات عملیاتی

داشبورد اصلی نقطه ورود شخصی کاربران است. ویجت پلنر و کارت پروفایل سازمانی در `/admin/index.php` نمایش داده می‌شوند و مسیرهای قدیمی پنل کارمند برای سازگاری به همین صفحه هدایت می‌شوند.

## پلنر

- افزودن سریع با CSRF انجام می‌شود و وظیفه برای تاریخ انتخاب‌شده یا امروز ذخیره می‌شود.
- رخدادهای روزانه، هفتگی و ماهانه پیش از نمایش بازه ساخته می‌شوند.
- `recurrence_key` از وظیفه مادر و تاریخ ساخته می‌شود و مانع رخداد تکراری است.
- تاریخ‌ها در UI شمسی و در ستون‌های `DATE` میلادی نگهداری می‌شوند.

## تغییرات داده‌ای امن

- `work_planner_tasks.recurrence_key` و ایندکس یکتای آن فقط در صورت نبودن افزوده می‌شوند.
- `hr_attendance_settings.effective_to` اختیاری است و بازه‌های فعال یک گروه نباید هم‌پوشانی داشته باشند.
- `management_report_periods` با `CREATE TABLE IF NOT EXISTS` ایجاد می‌شود.
- `file_backup_api_key_rotated_at` فقط زمان چرخش کلید را نگه می‌دارد؛ مقدار خام کلید ذخیره نمی‌شود.

## امنیت و خطاها

- اعلان‌های `ticket_*` فقط با گزینه داخلی `system_authorized` برای مسئول تیکت ساخته می‌شوند.
- خطاهای فنی ایمیل در log و `last_error` ثبت می‌شوند و UI پیام فارسی کنترل‌شده دارد.
- تخصیص قالب KPI باید پیش از امتیازدهی وجود داشته باشد و scope پرسنل بررسی می‌شود.

## Rollback

Rollback کد با revert commit انجام می‌شود. جدول‌ها، ستون‌ها و داده‌های افزوده‌شده حذف نشوند؛ باقی‌ماندن آن‌ها با نسخه قبلی ناسازگاری ایجاد نمی‌کند.
